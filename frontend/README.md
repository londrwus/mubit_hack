# Busy Machines frontend

Vite + React + TypeScript + Tailwind CSS (v4), with shadcn/ui-style components (`src/components/ui`) and lucide icons. It builds the approved Pen screens in `design/exports/final/`:

| Route | Pen frame | What it shows |
|---|---|---|
| `/` | `pOKAY` (landing: hero, engine, our model, benchmarks, call to action) | Logged numbers only, read from `data/frontend/showcase.json` |
| `/app` | `P6OjMG` (Get started) | The three onboarding steps: Mubit key, compute, start a sweep |
| `/app/compare` | `GKsLR` (Compare) | The standard Opus 5.5 agent vs Busy Machines, replayed live from the backend |

## Run it

1. **Backend** (PowerShell, repo root). Replays need the logged races: the committed exports in `data/bench/` (or your local `data/bench/bench.db`):

   ```powershell
   $env:PYTHONUTF8="1"; $env:PYTHONIOENCODING="utf-8"
   $env:BUSY_MACHINES_REPLAY_SOURCES="data/bench"
   python -m uv run --extra ml --with onnxruntime==1.29.0 uvicorn backend.app:app --port 8765
   ```

   A replay makes no LLM call and no Modal call, so it costs nothing.

2. **Frontend** (in `frontend/`):

   ```powershell
   npm install
   npm run dev        # http://localhost:5173
   ```

   `npm run build` type-checks the code and writes `dist/`. `npm run typecheck` only type-checks.

The API base is `VITE_API_BASE` (default `http://127.0.0.1:8765`). See `.env.example`.

The backend allows CORS from `http://localhost:5173` and `http://127.0.0.1:5173` by default. To set other origins, give `BUSY_MACHINES_CORS_ORIGINS` a comma-separated list. To turn CORS off, set it to an empty string. CORS covers HTTP only; the WebSocket does not need it.

## Where the numbers come from

- **Landing (`/`).** `npm run dev` and `npm run build` first run `scripts/sync-data.mjs`, which copies `../data/frontend/showcase.json` into `src/data/` (git-ignored). That file is generated by `scripts/build_showcase.py`, and every number in it is checked against `docs/results_log.md`. The page reads each value from it: R78 (game-playing, mean of 3 runs), R87 (time to the goal), R82 (tabular AI bill) and R81 (0 vs 57 of 109 fakes caught). The landing never shows a number that is not in that file, except two text lines kept from the approved design: "ONE H100 · ABOUT $1 OF COMPUTE · R33, R42" and the R54 field note ("A sweep reported 99.9%. On fresh data it scored 88.7%."). Both are logged rows. The field note is one run of the no-AI tool's shipped image model in R54 (self-reported 0.9994, held-out 0.8874; the other two runs 1.0 → 0.8852 and 0.9994 → 0.914), not a Sapling result.
- **Compare (`/app/compare`).** Picking an example replays run 1 of that logged race at 90×. The page calls `POST {API}/api/races/{prefix}/replay?speed=90&metric_stride=0` and then reads ticks from `WS {API}/ws/replays/{id}/dashboard` (`docs/dashboard_api.md`). It uses R78 run 1 (`4ca4ed27`) and R82 run 1 (`c1f4b1d9`); the race ids come from `showcase.json`. Every number on the screen comes from those snapshots. The chips ("4× cheaper, mean of 3 runs", "Same quality" / "Within the set margin") are the logged 3-run results, and they appear only once the replay has finished.
  - If the backend is offline, the game-playing example shows R78 run 1's logged end values (R90), and the tabular example shows the R82 3-run means. Both are labelled.
  - "Catching hallucinated wins" is a static R81 result from `showcase.json`: the published Banyan Sapling vs our sapling-research v2 (looser setting).
  - Every example shows its `worse_side` line from `showcase.json` ("Where it falls short"), as display rule 1 requires.

## Known gaps and TODOs

- **Hugging Face links:** `src/lib/links.ts` points at https://huggingface.co/busy-machines/sapling-research and https://huggingface.co/datasets/busy-machines/ml-claims, both public since R92.
- **The hero still says "Your GPUs should never wait"** (from the Pen frame `KekD1`). D54 says "machines" or "compute", never "GPUs" alone (our best results ran on CPU workers, R78, and simulated GPU time, R82), so change that copy before the landing page is shown.
- **The Compare page replays at 90× only.** Its server-set tag reads "· 90× speed"; the video's 30× takes use `scripts/replay_tui.py` (`docs/video_script.md`).
- **The time-to-goal panel (R87) needs its full caveat.** The caption says the game task's goal is easy; the log's caveat also says the no-AI tool reached it cheapest ($0.009 / 0.4 min, R78, R87).
- **The Get started API block is not the design's one-liner.** `POST /api/races` takes a full `RaceConfig`; it has no `{"preset": ...}` shortcut (see `design/exports/final/README.md`). So the block shows `POST /api/races` with the start of the preset's real body (marked `…`), then `POST /api/races/{id}/start`. **Copy** copies the full request as curl. That body equals `PRESETS["rl-wide-bm-cadence-15m"]`; we checked it with `RaceConfig.model_validate`. The CLI line is the real `scripts/bench.py` form.
- **"Start a sweep" does not start anything.** A real sweep calls Opus 5.5 through Mubit and runs on Modal, so the button only copies the CLI command.
- **Steps 1 and 2 are static.** Their "Done" ticks, the masked key and the Modal token come from the design; the page does not check them against the backend.
- **The machine grid shows real data only.** While a replay runs, each tile is that slot's real state. A finished sweep has every slot off, so at the end the grid switches to the whole sweep: filled tiles = share of machine time spent training (100% − the snapshot's machines-waiting value, e.g. R78 run 1: 31.0% vs 98.6%, logged in R90), labelled "Machine time spent training, whole sweep". The design's "9 of 30 training" snapshot is not used as such; on R78 run 1 the whole-sweep view happens to fill 9 of 30 tiles.
